# MCP reliability and circuit analysis plan

Planning baseline: commit `9734f36`, reviewed September 7, 2026. The findings and line references below describe that baseline. The supported reliability and linear-analysis implementation is now in native API 2 / Python 0.2; see [the implementation contract and limits](mcp-analysis.md). Broader SPICE, nonlinear models and hierarchy expansion remain follow-on work.

Build trustworthy project snapshots and edit semantics first, then electrical interpretation, then reproducible analysis. Keep project interpretation and mutation in Swift so the app, CLI, Python package, and MCP agree. Put numerical analysis in a separate Python module over an immutable native snapshot, with thin MCP tools.

**1. Establish source selection, diagnostics, and consistent snapshots**

Proposed contract: `open_project(path, source="auto" | "live" | "disk")` returns an opaque `project_ref`, requested/resolved source, transport, project identity, revision, and capabilities. `auto` resolves once at open; subsequent calls stay bound to that source. Explicit live selection fails if unavailable. Explicit disk selection always describes saved state. Opening both is supported through distinct references. A closed or lost live document never silently becomes a disk project.

Retain path shorthand for a single unambiguous open context. Reject ambiguous references rather than choosing the most recently used project. Source selection and transport selection are separate: disk can use a worker or in-process engine, while live uses the app connection. Closing an MCP context releases the client reference without closing or unregistering the user's document.

Add `connection_status`, available before any project opens. Report discovery attempts and failures, authenticated handshake status, engine/API/MCP versions, native binary path and build identity, endpoint identity, latency, supported features, and open contexts. Never expose the auth token. No discovery file proves only that a live endpoint is unavailable; the app may be stopped, automation disabled, or no documents open. Report uncertainty instead of guessing which condition applies. Identify stale release binaries, since current native discovery prefers release over debug.

Introduce one read-only snapshot/file-provider abstraction for model, block JSON, pool files, and dependency resolution. Live snapshots read the document archive; disk snapshots capture the loaded files and manifest. Remove direct disk reads from snapshot consumers, including the design index and editor's pool resolution. Capture or explicitly mark any external dependencies. A missing live dependency must not silently fall back to a newer disk file.

Expose two distinct identities: an opaque edit `revision`, scoped to project/source/document instance, and a content-based `snapshot_id` for reproducibility. Live revisions need a dedicated monotonic design counter plus a fresh document/server instance ID, with coverage of edits, undo/redo, pool changes, and reloads. Disk revisions include a content fingerprint of the manifest and consumed dependencies; timestamps alone are insufficient. Hash snapshots deterministically, with stable UUID tie-breakers and ordering independent of locale. Keep selection/viewport state separate from design revisions. Report saved/unsaved status only from a reliable saved-state baseline.

Every new structured query result identifies its source and snapshot. Image results carry structured sheet, region, and revision metadata alongside the PNG. Multi-call analysis uses a pinned snapshot with explicit lifetime/expiration, rather than assuming consecutive live reads saw the same revision.

Acceptance: open live and disk copies with deliberately different unsaved component, group, and pool changes; every field and render must use the selected snapshot. Verify source pinning, document close/reopen, undo/redo, path aliases, stale disk state, and dependency changes.

**2. Fix selectors, typed contracts, and errors**

Expose `get_net(name=None, id=None)` and component UUID lookup, requiring exactly one selector. Reject empty name selectors; an unnamed net remains addressable by UUID. Apply the same identity rules to highlight, selection, zoom, and edits. Return stable component, net, gate, pin, symbol, sheet, and block IDs so callers never need to recover identity from labels.

Create a shared sheet resolver supporting UUID or a uniquely resolved block/index/name. Missing selectors return `NOT_FOUND`; multiple matches return `AMBIGUOUS_SELECTOR` with candidate IDs. Only a valid sheet with no components returns an empty list. Validate render layers too: the current renderer silently disables every layer for an unrecognized name. Distinguish block definitions from instantiated circuits; reject unsupported hierarchical edits until the editor can target them correctly.

Use explicit Python models for requests/results, selectors, regions, and edit operations discriminated by `op`. Enforce the same rules at native dispatch so CLI/direct callers cannot bypass validation. Prefer native method/operation descriptors as the shared contract source, with generated schema fixtures and parity tests. Validate unknown fields, wrong scalar types, finite numbers, ranges, and mutually exclusive selectors.

Define errors with stable `code`, `message`, structured `details`, `retryable`, and `outcome` where relevant. Initial codes include `INVALID_ARGUMENT`, `NOT_FOUND`, `AMBIGUOUS_SELECTOR`, `LIVE_UNAVAILABLE`, `AUTH_FAILED`, `CONNECTION_LOST`, `TIMEOUT`, `STALE_REVISION`, `READ_ONLY`, `UNSUPPORTED_MODEL`, `TRANSACTION_INDETERMINATE`, and `RECOVERY_REQUIRED`. Preserve native details through Python. Expected execution failures must set MCP `isError`; an `{error: ...}` object must not be presented as success. Typed successful results and tool errors should follow the [MCP tool result/schema contract](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).

Version changes that alter list envelopes or require edit preconditions. Keep existing scalar fields where their meaning remains valid, document migration, and test advertised schemas against the actual SDK output rather than assuming annotations alone enforce them.

Acceptance: unnamed UUID nets, contradictory selectors, duplicate names/refdes, duplicate sheet numbers across blocks, invalid sheets versus valid empty sheets, invalid layers, malformed operations, and end-to-end structured failures through an MCP client.

**3. Bound waits and make edits recoverable**

Implement a connection manager that closes failed sockets, rediscovers/authenticates endpoints, checks capabilities, and reacquires handles using project and document identity. Validate JSON-RPC response IDs and framing. Retry side-effect-free reads at most once within the original deadline; an expired pinned snapshot must fail rather than quietly query a different one. Detect app restarts and document instance changes explicitly.

Use configurable total deadlines covering lock acquisition, queue time, connect, write, and read. Set limits on line length, response size, queued requests, and operation count. Discard a timed-out connection to avoid treating a delayed response as the next response. A timeout does not establish whether a write happened.

Hard cancellation cannot safely interrupt an arbitrary synchronous ctypes call. Make a worker subprocess the default disk engine for MCP if hard time bounds are required; retain in-process mode for Python users with documented cooperative limits. [Live requests currently execute on the main actor](/Users/kornack/Repositories/horizontal/Sources/HorizontalNative/Dispatch/HorizontalLiveServer.swift:239). Capture a snapshot there, run eligible expensive reads and analysis off the main actor, then revision-check commits there. Audit rendering/export APIs before moving them. Check cancellation before commit; do not interrupt a transaction in its commit-critical section.

Require `expected_revision` for every design mutation, including convenience tools, pool writes, and group layout copies. Compare it against the actual current source under the same synchronization as mutation; never fill it with the current revision inside the server. Dry runs return the base revision, normalized operations, changed-file previews, and a plan digest. Commit checks both revision and plan. Return before/after revisions and whether changes reached memory or disk. Cover direct native dispatch, not just MCP wrappers.

Add mutation `operation_id` and `transaction_status`. Persist a receipt together with disk transaction state; bind an operation ID to its payload digest and reject reuse with different operations. A lost response triggers status lookup, never blind replay. Live mutation receipts can resolve uncertainty while the document instance survives; an app crash can lose an unsaved edit, so durable receipt metadata alone must not claim the edit survived.

Implement a transaction coordinator in ProjectIO and use it for editor/pool batches. Stage and validate all post-edit files before changing targets. Record original/new hashes, backups, created paths, operation ID, and transaction phase in a durable journal. Acquire project-level coordination, recheck original contents, install same-volume replacements, verify the installed project, and write the commit receipt before cleanup. Preserve Horizon formatting and untouched files. Allow pool creation and dependent design operations to share one transaction, which the atopile importer needs.

On open after interruption, recover before serving the project. Roll back uncommitted work or finish a recorded commit using file hashes and recorded phase. If a target matches neither recorded old nor new content, retain backups and return `RECOVERY_REQUIRED` instead of overwriting external changes. Treat post-commit reload failure separately from an uncommitted failure. Account for `.hprj` sibling files and references outside the package; do not assume one directory rename can cover all targets. The app's in-place save path must participate in recovery/coordination if the guarantee is to cover saves as well as MCP writes.

Issue: project locks coordinate cooperating writers; unrelated editors can still race. Journaled multi-file recovery does not provide atomic visibility to arbitrary external readers. State the guarantee as recoverable consistency for participating Horizontal readers/writers, and detect conflicts rather than promise universal atomicity. Refuse disk edits when a conflicting open Horizontal document is positively known; endpoint unavailability cannot prove no editor is holding the files.

Acceptance: disconnect before/after send and after commit; stale token; app/worker restart; stalled response; concurrent edits; stale dry run; injected failure at every file replacement/journal phase; process kill and recovery; rollback conflict; reload failure; and repeated operation IDs. Live edits must still be one undo step. Network tests that skip because a listener cannot start are not evidence that reconnection works; add deterministic fake-transport tests and an integration environment that requires the live suite to run.

**4. Build the electrical snapshot and operating scenarios**

Resolve physical terminals through component part → inherited base part/pad map → package pad UUID/name. Existing [part models](/Users/kornack/Repositories/horizontal/Sources/HorizontalNative/Model/Pool/HorizontalPoolPartItem.swift:88) and [board mapping code](/Users/kornack/Repositories/horizontal/Sources/HorizontalNative/Model/HorizontalBoard.swift:3478) provide the starting point; extract shared resolution instead of duplicating it. Return a list of physical pads per logical pin, retaining names as strings for terminals such as `A1` and `EP`. Support unplaced components, multiple pads per pin, and missing mappings. Distinguish logical unconnected pins, explicitly marked no-connects, unmapped pads, and mechanical pads.

Return component raw value, resolved part value, effective value and its provenance. Parse supported engineering notation into typed SI quantities with parse status, source field, and explicit tolerance when available. Cover `4k7`, `10k`, `100n`, micro symbols, embedded units, and zero-ohm links. Never turn an MPN or ambiguous text into a plausible number. Component edits may be masked by a part's value; surface that distinction consistently in queries, BOM, edits, and analysis.

Define a versioned scenario describing assembly population, explicit substitutions/value overrides, jumpers, relay/contact states, supplies, sources, loads, temperature, and ADC configuration. Use native population flags as the baseline and record every override. Keep schematic connectivity intact; derive effective circuit connectivity for each scenario. Excluding a DNP component must remove its device contribution without deleting the schematic's nets.

Relay models declare contact pin groups, normal/energized states, and supplied on-resistance/leakage where applicable. Latching devices require an explicit state; coil voltage alone is insufficient. Do not infer contact topology from symbol placement, reference designator, or a guessed part name. Missing state/model data produces a list of requirements or explicitly enumerated scenarios, not an assumed closed path. Persist scenarios/model bindings in a versioned sidecar keyed by stable IDs, with hashes included in analysis identity; analysis does not change assembly flags in the design.

Acceptance: inherited mappings, multi-pad power pins, alphanumeric terminals, missing packages, unplaced devices, parsing failures, overridden part values, DNP branches, relay alternatives and latching states, hierarchical boundaries, and deterministic effective topology.

**5. Add reproducible analysis with schematic evidence**

First expose `analysis_snapshot` and `validate_analysis` so a caller can inspect the selected subcircuit, boundary ports/loads, models, assumptions, missing inputs, and evidence before calculation. Add four focused entry points using that same immutable input: `analyze_transfer`, `analyze_noise`, `analyze_headroom`, and `analyze_adc_filter`. Run long calculations as bounded background jobs with status/cancel/result calls.

| Analysis | Explicit inputs and deliverables | Limit that must remain visible |
|---|---|---|
| Transfer function | Input/output node pairs, reference/source normalization, loading, frequency grid, device models; return complex gain, magnitude, phase, and defined bandwidth metrics. | Begin with supported linear networks and declared amplifier models; reject unsupported nonlinear devices and incomplete hierarchical connectivity. |
| Noise | Temperature, bandwidth, frequency grid, component/device PSD models and correlation assumptions; return per-source output/input-referred spectra and integrated RMS contributions. | Label PSD versus amplitude density and one/two-sided conventions. Missing device noise is unknown, not zero; a partial calculation cannot be labeled total circuit noise. Use a recorded seed only for sampled tolerance/Monte Carlo work. |
| Headroom | DC operating point, signal amplitude/convention, supplies, reference, loads, amplifier common-mode/output limits, and ADC input limits; return limiting nodes/devices and margins. | Ideal transfer gain cannot establish clipping margin or guaranteed device performance. Missing limits block those conclusions; nominal, typical, and guaranteed limits remain distinct. Dynamic settling/slew limits require appropriate models. |
| ADC filter | Exact converter/model, clocks, sampling/output rates, register/filter mode, coefficients or documented response, analog front end, and input spectrum; return passband, notches, delay/settling where supported, and alias/noise estimates. | Analog anti-alias filtering and digital decimation are separate stages. Digital filtering cannot undo noise already aliased into band. Datasheet/configuration evidence is required; arbitrary sinc assumptions are not acceptable. |

Start with a deliberately bounded linear numerical backend and closed-form reference circuits. Evaluate an isolated ngspice adapter for wider device-model support once the snapshot/model contract is stable; document compatibility and model redistribution constraints before making it a dependency. Use the [official ngspice documentation](https://ngspice.sourceforge.io/docs.html) for backend behavior and pin the selected engine version. General SPICE import/model acquisition and nonlinear transient simulation are separate follow-on scope.

Every result includes snapshot/content digest, source/revision, normalized request and scenario, model files and hashes, engine/algorithm/dependency versions, temperature, frequency/integration settings, tolerances, and seeds if applicable. Numerical reproducibility means stated tolerances across supported platforms, not an untested promise of identical floating-point bytes.

Attach each modeled component and conclusion to component/net/gate/pin IDs, physical pad names, block/instance and sheet/symbol IDs, a bounding region, and source file/JSON location from the snapshot. Datasheet parameters include document version/hash and page/table references; user-supplied parameters are labeled as such. Provide immutable schematic crops from the same snapshot and an exportable bundle of inputs, model bindings, numeric data, report, and plots. Cache by full normalized inputs plus model/engine hashes. Never relabel cached results as the current design after an edit.

Acceptance: analytic resistor divider, loaded RC pole, resistor thermal noise over a defined band, RC noise integration, declared amplifier noise, known headroom boundary, explicit ADC coefficient response, and combined analog/decimation example. Verify dimensional consistency, frequency-grid convergence, scenario changes, missing-model errors, and replay from the exported bundle. Use selected independent simulator comparisons where device models are supported. Do not accept a chart as proof of correctness.

**Delivery order and decisions**

Implement as six reviewable changes: (1) immediate UUID/sheet fixes with focused regression tests; (2) source-bound contexts, diagnostics, and complete snapshot/revision identity; (3) typed contracts and migration; (4) deadlines, reconnection, guarded edits, and transaction recovery; (5) physical terminals, values, and scenario models; (6) analysis tools in the order transfer → noise → headroom → ADC filter. The first small fix need not wait for the full contract migration. The reliability release consists of changes 1–4; it can ship before analysis.

The largest scope variables are complete mutation-counter coverage, app save coordination, block-instance expansion, and availability of validated amplifier/ADC models. Initial analysis should explicitly support a selected, fully resolved subcircuit; broader hierarchy must pass its own topology tests before being advertised. Pick one representative project and its actual ADC/amplifier configuration as an integration fixture after the synthetic contracts are working. No particular device model or operating configuration has been supplied in this request, so this plan does not claim to validate one.

This planning pass inspected source and the installed MCP schemas and reproduced the invalid-sheet behavior on a temporary project. It did not modify the server or run the full Swift/Python suites.
